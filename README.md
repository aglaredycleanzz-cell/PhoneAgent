# Phone Agent

**مساحة عمل عربية لإنجاز مهام الهاتف — بخطة واضحة، وصلاحيات تحت سيطرتك، ونتائج يمكن مراجعتها.**

Phone Agent تطبيق Android أصلي مبني بـ Kotlin وJetpack Compose. الواجهة الأمامية أصبحت مساحة حوار مع ثلاثة رفقاء بصريين، بينما يعرض تبويب النشاط الطلبات العملية في سجل محلي.

## اتجاه المنتج

Phone Agent ليس مجرد محادثة مع أفاتار أو وعدًا بالتحكم الكامل. توجهنا هو جمع الحوار العربي، وتخطيط المهام، والموافقة الصريحة، وسجل التنفيذ والتحقق في تجربة واحدة. راجع [استراتيجية المنتج وتحليل المنافسين](docs/PRODUCT_STRATEGY.md) لمعرفة الفئة المستهدفة، والفارق المقترح، وخارطة الطريق.

## الحالي في هذا الإصدار

- ثلاثة أفاتارات مميزة: **NOVA** للتخطيط، **ORION** للمهام التقنية، و**SENTINEL** لمراجعة الأمان.
- واجهة RTL عربية تتضمن فقاعات الحوار، اقتراحات سريعة، محرر رسائل، وتبديل الرفيق.
- حفظ سجل المحادثات محليًا حسب الرفيق، ضمن مساحة التطبيق الخاصة.
- تصنيف بسيط قائم على قواعد محلية للتمييز بين النقاش والطلبات العملية.
- الطلبات العملية الواضحة تُحفظ تلقائيًا في سجل النشاط كمسودات فقط.
- صفحة نشاط تعرض المسودات وحالة محرك التنفيذ.
- شاشة ثقة توضح حدود الصلاحيات الفعلية.
- لا يوجد إذن `INTERNET`، ولا خدمة Accessibility، ولا منفّذ أوامر، ولا اتصال بنموذج ذكاء اصطناعي.
- اختبارات وحدة لاكتشاف الطلبات العملية والتحقق من الإفصاح عن حدود النظام.
- GitHub Actions يشغّل الاختبارات ويبني APK تجريبيًا.

## ملاحظة مهمة حول المحادثة

الأفاتارات والواجهة تفاعلية، لكن ردود هذه النسخة تجريبية وقائمة على قواعد محلية، وليست نموذجًا لغويًا حقيقيًا. لا يقرأ التطبيق تطبيقات أخرى ولا ينفّذ أوامر الهاتف بعد. هذا فصل مقصود حتى لا نعرض قدرات وهمية قبل ربط نموذج ومحرك إجراءات واختبارهما.

## تنزيل APK

1. افتح [Actions](../../actions).
2. اختر أحدث تشغيل ناجح باسم **Android CI**.
3. نزّل `PhoneAgent-debug-apk` من قسم **Artifacts**.
4. فك الضغط وثبّت `app-debug.apk` على هاتفك.

هذه نسخة Debug للتجربة وليست إصدارًا إنتاجيًا موقّعًا.

## البناء

المتطلبات: JDK 17 وAndroid SDK 36 وGradle 8.13.

```bash
gradle --no-daemon :app:testDebugUnitTest
gradle --no-daemon :app:assembleDebug
```

## مراحل التطوير التالية

1. إضافة طبقة محادثة حقيقية عبر نموذج يُختار بوضوح؛ لا تُرسل البيانات للخارج افتراضيًا.
2. إضافة خدمة Accessibility اختيارية مع فتح إعدادات أندرويد يدويًا من المستخدم.
3. بناء محرك إجراءات محدود وقائمة سماح، ومعاينة لكل إجراء، وموافقة على العمليات الحساسة، وإلغاء وسجل تدقيق.
4. إظهار التنفيذ الجاري والنتائج الفعلية في تبويب النشاط.
5. اختبار التطبيق على جهاز حقيقي قبل الادعاء بقدرته على التحكم.
